# FTAS 答辩演示脚本（3 分钟）

> **三种演示形态，任选其一即可完成答辩：**
>
> | 形态 | 需要什么 | 适用场景 |
> |---|---|---|
> | **A. 远程在线**（主方案） | 云服务器已部署 + 教室电脑能上网 | 服务器已开通、会场网络可达 |
> | **B. 远程离线模式** | 同上，容器以空 Key 启动 | 会场能连服务器、但网络不稳 |
> | **C. 离线静态包**（终极兜底） | 一个 U 盘 + 任意一台有浏览器的电脑 | **零网络、零服务器、零安装** |
>
> 演示机是台式机不便携带时：**方案 A/B 用教室电脑的浏览器即可**，C 连服务器都不需要。

## 演示前准备

### 方案 A / B：服务器远程演示（需先按 `deploy/README.md` 部署）

在服务器上（ssh 登录后执行）：

```bash
cd /path/to/FTAS
# 方式 A：实时模式（调用 DeepSeek，单次约几分钱）
docker compose up -d

# 方式 B：离线模式（零 API 扣费、不依赖外网）
OPENAI_API_KEY= docker compose up -d --force-recreate
```

验证：

```bash
curl http://<服务器IP>:<端口>/api/health
# 实时模式 → {"status":"ok","llm_configured":true}
# 离线模式 → {"status":"ok","llm_configured":false}
```

> ⚠️ **必须提前到答辩场地实测一次**：用教室网络和手机热点各访问一次
> `http://<服务器IP>:<端口>`，确认能打开。这是方案 A/B 唯一的命门。

### 方案 C：离线静态演示包（U 盘）

本机生成（已生成过可跳过）：

```bash
cd /Users/zhangsong/Desktop/FTAS
.venv/bin/python scripts/export_static_demo.py     # 输出到 demo_static/
```

把整个 `demo_static/` 目录拷进 U 盘 → 现场**双击 `index.html`** 即可演示。
**注意必须整个目录一起拷**（页面用相对路径引用 `figures/` 下的图片）。

## 演示流程（按时间轴）

**0:00–0:20 开场定位**
打开页面 → 指标题「⚽ FTAS 足球战术分析系统」→ 滑到页脚，说明数据来源：StatsBomb 开放数据（CC BY-NC-SA 4.0，非商业用途）。

**0:20–0:40 查询比赛（交互第一步）**
① 球队名称输入 `Barcelona` → ② 赛事关键词留空 → 点「查询比赛」→ ③ 下拉选择 `2021-04-22 | La Liga | Barcelona 5-2 Getafe`。
（方案 C 离线包：直接点击顶部的比赛按钮切换。）

**0:40–1:30 一键分析（交互第二步，核心展示）**
提示词保持默认（或改为「分析这场比赛的战术风格和进攻偏好，并点评核心球员」）→ 点「分析」→ 展示 loading 状态 → 出结果：
- 来源徽标：实时模式为绿色「实时分析」，离线模式为黄色「离线缓存结果」，离线包为「离线静态演示包」——**主动说明这是设计好的离线兜底机制**
- 三张图 + 团队统计对比表 + 核心球员表 + 中文战术分析全文

**1:30–2:00 讲解三张图**
- 传球网络：节点大小 = 传球次数，连线粗细 = 传球频次，位置 = 球员平均站位
- 射门分布：蓝点 = 射门未进，红点 = 进球
- 活动热力图：全队触球位置密度

**2:00–2:30 讲解三组战术指标（摘要 Schema v2）**
- 战术风格：阵型、平均传球长度、长传占比、每控球传球数、前场压迫次数
- 进攻偏好：左/中/右路占比、传中、直塞、平均射门距离、禁区内/外射门
- 核心球员：综合分 `goals×5 + key_passes×3 + shots×1 + network_degree×0.5 + passes×0.05`，取前 5

**2:30–3:00 两个加分点 + 收尾**
- 防幻觉（仅方案 A 可现场演示）：把提示词改成「请告诉我这场比赛的预期进球 xG 是多少」→ 模型回答「数据不足，JSON 中没有 xG 字段」——证明模型只引用统计数据、不编造
- 架构一句话：StatsBomb 开放数据 → FastAPI（Docker 容器）→ 统计管线产出摘要 JSON + 三图 → DeepSeek 生成战术解读 → 静态前端展示

## 现场应急手册

| 情况 | 处置 |
|---|---|
| 教室电脑打不开服务器地址 | 换手机热点重试；仍不通 → 切**方案 C 离线包**（U 盘双击） |
| 服务器/容器全挂 | 手机 ssh 上去 `docker compose restart`；来不及 → 切**方案 C 离线包** |
| 一切电子设备都出问题 | 播放**提前录好的演示视频**（U 盘 + 云盘 + 手机各存一份），配合架构讲解 |
| 会场断网但服务器可达 | 方案 B（空 Key）下一切照常，徽标显示「离线缓存结果」 |
| 老师想换一支球队 | 方案 A 可现场查询任意球队并实时下载；方案 B/C 只能用预置场次（可提前多预置几场） |
| 页面打开但报错 | `curl http://<IP>:<端口>/api/health` 确认服务活着；`docker compose logs ftas` 看日志 |

## 答辩可能被问到的问题（答案速查）

1. **数字怎么保证准确？** 所有统计由 pandas 管线计算（口径注释在 `src/analysis/summary.py`），模型只拿到摘要 JSON，被系统提示词禁止引用 JSON 之外的数据，后端还有 `validate_output` 二次校验（不合格自动纠错重试一次）。
2. **模型会不会编造？** 有防幻觉双层防线：提示词约束 + 输出校验；现场可演示 xG 陷阱问题。
3. **多用户并发怎么办？** 数据层按 match_id 命名空间缓存（`data/cache/{match_id}/`），进程内无全局可变状态；`/api/analyze` 按 IP 限流。
4. **为什么用 Docker？** 一键部署、依赖与中文字体打包进镜像、`restart: unless-stopped` 保证重启自愈。
5. **为什么会有离线包？** 答辩演示的可用性优先于实时性：结果是预生成快照，保证任何环境下都能完整展示系统能力。
6. **数据许可？** StatsBomb 开放数据，CC BY-NC-SA 4.0，仅限非商业用途，页面已署名。
